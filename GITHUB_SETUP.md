# Publishing Coverage Navigator to GitHub

A start-to-finish walkthrough. Replace `YOUR-USERNAME` with your GitHub username
throughout.

---

## Step 0 — Assemble the folder

Create a folder on your computer called `coverage-navigator` and arrange the
files exactly like this:

```text
coverage-navigator/
├── .gitignore
├── LICENSE
├── README.md
├── QUICKSTART.md
├── app.py
├── requirements.txt
├── data/
│   └── synthetic_coverage_cases.csv
├── model/
│   └── model_card.md
├── src/
│   ├── train_model.py
│   └── make_figures.py
├── docs/
│   ├── index.html
│   ├── governance.md
│   ├── pilot.md
│   └── images/
│       ├── issue_rate_by_service.png
│       ├── risk_score_distribution.png
│       └── subgroup_monitoring.png
└── notebooks/
    └── README.md
```

Two things to note:

- `model/coverage_navigator_demo.joblib` and `model/metrics.json` are **not** in
  this list. They are generated by the training script. The `.gitignore` file
  excludes the `.joblib` binary; commit `metrics.json` once you have run
  training so the project page can cite real numbers.
- Folder names must match exactly, including lowercase. `app.py` looks for
  `data/synthetic_coverage_cases.csv` at that precise path.

## Step 1 — Verify it runs before you publish

Do this first. It is much less painful than discovering a broken demo after
you have shared the link.

```bash
cd coverage-navigator
python -m venv .venv
source .venv/bin/activate          # Windows: .venv\Scripts\activate
pip install -r requirements.txt

python src/train_model.py          # writes model/metrics.json
python src/make_figures.py         # regenerates docs/images/
streamlit run app.py               # opens the demo in your browser
```

Click through all four pages. Confirm the sidebar says "Trained model loaded."
Press Ctrl+C to stop the server when you are done.

## Step 2 — Create the repository on GitHub

1. Go to <https://github.com/new>.
2. Repository name: `coverage-navigator`
3. Description: `AI-assisted pre-service coverage decision support — human-in-the-loop portfolio project`
4. Select **Public**.
5. Do **not** check "Add a README file", "Add .gitignore", or "Choose a license".
   You already have all three, and letting GitHub create them causes a merge
   conflict on your first push.
6. Click **Create repository**. Leave the page open.

## Step 3 — Push your files

From inside your `coverage-navigator` folder:

```bash
git init
git branch -M main
git add .
git status                         # read this before committing
```

`git status` should list your source files and **not** list `.venv/`,
`__pycache__/`, or the `.joblib` file. If it does, your `.gitignore` is not in
the folder root — fix that before continuing.

```bash
git commit -m "Coverage Navigator: human-in-the-loop coverage decision support"
git remote add origin https://github.com/YOUR-USERNAME/coverage-navigator.git
git push -u origin main
```

If GitHub asks for a password, it wants a Personal Access Token, not your
account password. Generate one at **Settings → Developer settings → Personal
access tokens → Tokens (classic)**, give it `repo` scope, and paste it as the
password. Alternatively install the [GitHub CLI](https://cli.github.com) and run
`gh auth login` once.

## Step 4 — Turn on GitHub Pages

1. In your repository, go to **Settings → Pages**.
2. Under "Build and deployment", set Source to **Deploy from a branch**.
3. Branch: `main`, folder: `/docs`. Click **Save**.
4. Wait two or three minutes, then visit:
   `https://YOUR-USERNAME.github.io/coverage-navigator/`

If the images are missing, check that the files are in `docs/images/` and that
the filenames match exactly — GitHub Pages is case-sensitive even though macOS
and Windows are not.

## Step 5 — Deploy the live demo

This is the step that matters most for a portfolio. Most people will not clone
your repository, but they will click a link.

1. Go to <https://share.streamlit.io> and sign in with GitHub.
2. Click **Create app** → **Deploy a public app from GitHub**.
3. Repository: `YOUR-USERNAME/coverage-navigator`. Branch: `main`. Main file
   path: `app.py`.
4. Click **Deploy**. The first build takes a few minutes.

You will get a URL like `https://coverage-navigator.streamlit.app`.

Note that Streamlit Cloud will not run your training script, so the deployed
app falls back to the transparent rule-based scorecard unless you commit the
model file. That fallback is intentional and the app says which mode it is in.
If you would rather show the trained model live, remove the `model/*.joblib`
line from `.gitignore`, run training, and commit the file — it is small.

## Step 6 — Add the links back into the project

Once you have both URLs, fill them in:

- **`docs/index.html`** — replace the two `#` placeholders in the header links
  with your Pages URL and Streamlit URL.
- **`README.md`** — add them under the title.
- **Repository sidebar** — on the repo home page, click the gear icon next to
  "About", paste the Streamlit URL in the Website field, and add topics:
  `responsible-ai`, `healthcare`, `ai-governance`, `streamlit`, `policy`.

Then commit:

```bash
git add docs/index.html README.md
git commit -m "Add live demo and project page links"
git push
```

## Step 7 — Add a screenshot

Run the app, take a screenshot of the Specialist Dashboard with the threshold
metrics visible, and save it as `docs/images/screenshot_dashboard.png`. Then add
this near the top of `README.md`, just under the opening question:

```markdown
![Coverage Navigator specialist dashboard](docs/images/screenshot_dashboard.png)
```

A reader decides whether to keep reading in about four seconds. An image of the
working tool does more in that window than three paragraphs will.

## Making changes later

```bash
git add .
git commit -m "Describe what changed"
git push
```

Both GitHub Pages and Streamlit Cloud redeploy automatically on push.

## If something goes wrong

**"Updates were rejected because the remote contains work you do not have"** —
you let GitHub create a README. Run `git pull origin main --allow-unrelated-histories`,
resolve any conflict, then push again.

**Streamlit Cloud build fails** — open the log from the app page. The usual cause
is a package in `requirements.txt` that does not exist or a typo in the main
file path.

**Demo loads but errors on a data file** — the CSV is not committed. Check with
`git ls-files data/`. If it is empty, the file was never added.
